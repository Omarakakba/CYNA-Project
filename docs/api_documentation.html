Vue d'ensemble de l'API

L'API REST de CYNA expose des endpoints JSON permettant l'accès programmatique au catalogue produits, aux catégories et aux commandes. L'API est construite en PHP natif (sans framework) et respecte les conventions REST standard.

Format de réponse

Base URL

Local (MAMP) : http://localhost:8888/cyna/api
Production : https://omar05.alwaysdata.net/cyna/api

Format des réponses

Toutes les réponses sont au format JSON UTF-8 avec l'en-tête Content-Type: application/json. Les réponses d'erreur incluent un champ error et un champ code HTTP.

Collection Postman : Le fichier docs/postman_collection.json peut être importé directement dans Postman ou Bruno pour tester tous les endpoints avec les requêtes préconfigurées.

Authentification

🔐 HTTP Basic Authentication

Les endpoints protégés (/api/orders.php) nécessitent une authentification HTTP Basic Auth :

  • Username : adresse e-mail du compte CYNA
  • Password : mot de passe du compte (en clair via HTTPS)

En-tête HTTP : Authorization: Basic <base64(email:password)>

3 — Commandes  Authentifié

Endpoint : /api/orders.php — Authentification HTTP Basic Auth obligatoire.

⚠️ Sécurité : Les identifiants sont transmis en Base64 dans l'en-tête HTTP Authorization. En production, l'API doit être servie via HTTPS pour chiffrer la transmission. Sur Alwaysdata, HTTPS est activé par défaut.
GET Auth Lister mes commandes
GET{{base_url}}/orders.php

En-têtes requis

En-têteValeurDescription
AuthorizationBasic <base64>Credentials utilisateur (email:password encodé en Base64)

Retourne uniquement les commandes de l'utilisateur authentifié. Un utilisateur ne peut pas voir les commandes d'un autre.

✅ 200 OK

GET Auth Détail d'une commande
GET{{base_url}}/orders.php?id=1

Paramètres de requête

ParamètreTypeRequisDescription
idintegerRequisID de la commande

Retourne le détail complet d'une commande (lignes, prix unitaires, durées, référence Stripe). Seules les commandes appartenant à l'utilisateur connecté sont accessibles.

❌ 404 — Commande inexistante ou appartenant à un autre utilisateur
{ "error": "Commande introuvable", "code": 404 }
4 — Importer dans Postman / Bruno

Postman

  1. Ouvrir Postman
  2. Cliquer sur Import (bouton en haut à gauche)
  3. Sélectionner File → choisir docs/postman_collection.json
  4. La collection CYNA API — Collection complète apparaît dans le panneau de gauche
  5. Configurer la variable base_url dans l'environnement (défaut : http://localhost:8888/cyna/api)
  6. Pour les commandes (auth) : configurer email et password dans l'onglet Authorization de la requête

Bruno (alternative open-source)

  1. Télécharger Bruno depuis usebruno.com
  2. Ouvrir une collection → sélectionner Import → Postman Collection
  3. Choisir docs/postman_collection.json
Test rapide via curl :

curl -s http://localhost:8888/cyna/api/products.php | python3 -m json.tool

curl -u "client@test.fr:Admin1234!" http://localhost:8888/cyna/api/orders.php
5 — Sécurité de l'API
MesureImplémentationFichier
Requêtes préparées PDO Tous les paramètres SQL sont passés via execute([]) — prévient l'injection SQL api/products.php
Échappement des sorties Toutes les chaînes de texte passent par htmlspecialchars() avant sérialisation JSON includes/security.php
Authentification Basic Auth Vérification email + password_verify() — hash bcrypt cost=12 api/orders.php
Contrôle d'accès Un utilisateur ne peut consulter que ses propres commandes (clause WHERE user_id = ?) api/orders.php
En-têtes de sécurité X-Content-Type-Options: nosniff, X-Frame-Options: DENY api/*.php
